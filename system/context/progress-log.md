### 2026-08-27 · feature · K1 keystone — one flow to one verdict, streamed full topology
Area: capture + ml-service + backend + frontend + infra. Built the keystone (spec 0002): one flow travels the whole spine, live. CSV replay publishes a flow record to Redis `flows`; the FastAPI ml-service subscribes, featurizes (L0.3), classifies with the single default model (the tree), and publishes a verdict to `verdicts`; the NestJS backend correlates flow+verdict by `flow_id` and pushes a merged row over a socket.io websocket; the React LiveFlows view renders it.
- **ml-service**: a model-generic loader (the manifest `default_model_id`), a family-aware score keyed on `supports_proba` (tree `predict_proba` calibrated; SVM `sigmoid(decision_function)` uncalibrated), an async `flows` subscriber run as a `lifespan` task with featurize+classify in one threadpool submission, `/ready` (the subscription-live gate) and `/predict` (isolated inference). scikit-learn pinned to 1.8.0; the image codegens the Pydantic contracts from `shared/schemas`.
- **capture**: a CSV-replay adapter behind the flow-record contract — reads a labeled CICIDS CSV, synthesizes the 5 tuple (the MachineLearningCVE files are feature only), carries the real Destination Port and `Label` → `ground_truth`, encodes non-finite rate cells (Infinity/NaN) as sentinel strings so the wire stays valid JSON across Python and JS, waits for ml-service `/ready`, replays at a fixed rate (shuffled for a lively demo).
- **backend**: an `ioredis` subscriber on both channels, a bounded correlation map swept by an active timer (both orphan directions), a relay-only socket.io gateway; the image codegens the TS contract types.
- **frontend**: the LiveFlows core ported from the design export (AppShell frame + a streaming DataTable with `animateNew` + `rowTone` alert, VerdictChip, ConfidenceMeter, StatusDot), one socket module, a 500 row cap.
Verified end to end: `docker compose up` cold-start ordering held (ml-service ready → backend subscribed → capture replays), 1500 flows classified with zero errors, malicious visibly flagged, and the verdicts match ground truth (MALICIOUS↔DDoS, BENIGN↔BENIGN). Locked with 36 unit tests (pytest: the score, the non-finite decode, the CSV mapping; Vitest: the correlation orphan edges) on top of the Layer 0 featurizer + contract suites. Spec 0002 → Accepted; build-graph K1 → ✅. The fan-out (F1 model switching, F3 metrics, F4 to F6 capture) is now unblocked.
Notes: (1) The manifest metrics are illustrative; the real `07_comparison` numbers land with the F1 registry. (2) capture gained `pandas` and `redis` (a `/sync` should add them to `library-docs.md`'s capture row). (3) The `uncalibrated` score indication in the UI is owed to the design system before an SVM is shown (F1); K1's default model is calibrated, so it is not exercised. (4) The featurizer-reject skip and the correlation orphan sweep are unit-tested but were not runtime-exercised in the demo run (clean data, immediate correlation). (5) The ml-service and backend build context is `system/` (so they codegen from `shared/schemas`); a `system/.dockerignore` keeps that context lean.
